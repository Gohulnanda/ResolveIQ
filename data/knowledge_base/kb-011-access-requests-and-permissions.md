## Summary
A user needs access to a folder, site or application, receives an access denied message, or a new employee needs an account.

## Symptoms
Opening a shared folder or site shows access denied. Access was approved but still does not work. A new starter has no account, mailbox or group memberships.

## Likely causes
- The user is not a member of the required security group.
- A recent role change removed earlier permissions.
- Group changes have not synchronised yet, or the session holds an old access token.
- The account request was never raised or approved.

## Resolution steps
1. Raise an access request naming the resource, the level of access needed and the business reason.
2. Make sure the data owner or manager has approved the request.
3. After approval, sign out and back in, or restart the computer, so that new group memberships apply.
4. Wait up to an hour for group changes to propagate before reporting that it did not work.
5. For a new starter, submit the onboarding form at least five working days before the start date with the role, manager and required groups.
6. Share the exact path or link of the resource that returns access denied.

## Escalate when
Access remains denied more than a day after approval, or access is requested to systems holding regulated or financial data without approval.
